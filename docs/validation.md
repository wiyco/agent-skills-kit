# Inert skill metadata validation

The library's `validation::parse_metadata` validates explicit SKILL.md bytes and a source directory name without filesystem access, environment discovery, script execution or host invocation. It is the pure first layer of ASK-007; the bounded read-only inventory below consumes it. Safe-copy execution is separate work. A parsed skill is not evidence of trustworthy content or successful host loading.

## Contract and preservation

Read against the [Agent Skills specification](https://agentskills.io/specification), **SKILL.md format / Frontmatter / name / description / compatibility / metadata / allowed-tools**, on 2026-10-16. Rolling specification, no format revision pinned by that page. Required name/description and known optional field types/limits are checked. Name equals the supplied source directory name; names have 1–64 Unicode lowercase/caseless alphanumeric characters or single hyphens, without edge/consecutive hyphens. The detailed Unicode wording governs the general rule; OpenCode's explicitly ASCII host grammar is checked separately. Unicode classification follows the Rust toolchain tables. This is not Unicode normalization or a promise that every host accepts every general-spec name.

As installer portability policy, reject Windows reserved device basenames even on Unix, including COM/LPT superscript-digit forms; separators, colons, traversal, controls and trailing spaces/dots are already excluded by the name grammar. Source: [Microsoft naming conventions, Naming conventions](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file), reviewed 2026-10-16. This restriction narrows the accepted specification names for safe destination components. It does not establish filesystem containment, case/normalization collision handling or no-follow safety.

Accepted input is UTF-8 with LF or CRLF, with standalone `---` opening/closing lines. A UTF-8 BOM is explicitly rejected rather than silently stripped. Preserve all accepted bytes exactly: line endings, extension fields, YAML spellings/comments, body and supporting references. `source_bytes()` is the eventual copy source; the metadata tree is for inspection, never YAML regeneration. `body_bytes()` is uninterpreted. Unknown scalar/sequence/string-keyed-map extension data is retained with positions and explicit scalar tags; tags are never instantiated. `metadata` must be string-to-string, and known scalar fields must be YAML strings rather than coerced numbers/bools/nulls. Core scalar interpretation follows [YAML 1.2.2, Core Schema / Tag Resolution](https://yaml.org/spec/1.2.2/), reviewed 2026-10-16.

For bounded processing, reject anchors/aliases (no expansion), merge keys, collection tags, complex/non-string map keys and duplicate keys at any depth. These are explicit parser-policy restrictions, not claims that the YAML specification forbids those constructs. Unknown scalar tags are inert retained data; explicit non-string tags on known string fields produce a type error. The parser does not load files referenced by any tag or field. Typed diagnostics include original line/column where available; missing fields and whole-input budgets point to the header. Error strings and metadata remain untrusted text and require escaping in a terminal renderer.

## Budgets

| Budget | Default | Hard ceiling |
| --- | --- | --- |
| Complete SKILL.md | 1 MiB | 16 MiB |
| Frontmatter | 64 KiB | 1 MiB |
| YAML scalar/collection nodes, including keys | 4096 | 65536 |
| Nested collections, including root | 16 | 64 |

Limits must be positive and cannot exceed hard ceilings. Size checks precede parser construction/tree allocation. Pull events stop on node/depth violations before recursive tree construction; recursion is capped. Input bytes bound individual scalar/scanner work and allocation. These finite bounds are not a universal CPU-time or allocator-failure guarantee. Filesystem entry/file/total/nesting budgets are defined below.

## Host constraints

`SkillMetadata::validate_for_target` is deliberately separate: Claude Code local reservations use the catalog's reservation query; OpenCode additionally requires its documented ASCII grammar. Host rules and sources are in [the core catalog review](catalog.md). General names and metadata must pass first. A host check does not prove effective permissions, discovery, or complete payload compatibility, and custom/unsupported host variants are not inferred as supported. The later planner must validate selected catalog scopes and call host constraints before writes.

## Bounded native source inventory

`inventory_skill` takes an explicit absolute source and `InventoryLimits`. It returns immutable metadata plus a complete `SourceInventory`, retaining a root handle, canonical/requested roots, native identity/mutation stamps, sorted relative paths, file types, output permission intent, BLAKE3-256 content digests and total bytes. Supporting resources and empty directories are included. No payload is executed or regenerated. Installation, destination collision checks, stale-plan revalidation and receipts are later layers.

The caller must control the root and ancestor namespace, as required by [the threat model](threat-model.md). Parent traversal/NUL/relative roots are rejected. Dot/trailing separators are removed lexically before the final-component no-follow root open, so a root symlink with `/` or `/.` cannot bypass rejection. Trusted ancestor canonicalization is recorded and checked against the opened root identity. Descendants use one-component `statat(SYMLINK_NOFOLLOW)` / `openat(NOFOLLOW | NONBLOCK | CLOEXEC | NOCTTY)` operations anchored to retained directories. Directory opens additionally require DIRECTORY. The lookup is a precondition, not authority: inspect the actual opened object's type/identity before reading, and compare metadata and entry binding afterward. NONBLOCK prevents a raced FIFO substitution from hanging before type verification. Unsupported static special entries are rejected before opening. No unsafe Rust is introduced in the runtime layer; native FFI is through reviewed rustix wrappers. Test setup invokes only a fixed system `mkfifo` utility to create owned FIFO fixtures, never a command from skill contents.

Reject descendant symlinks/dangling links, sockets, FIFOs, devices, multiply linked regular files and cross-device descendants. The resource component policy also rejects traversal/separators, Windows-invalid ASCII characters, control characters, reserved device stems (including padded/extensions/superscript forms), and trailing dots/spaces. Native non-UTF-8 resource identity is retained on Linux filesystems that permit it; the actual macOS APFS test rejects creation with EILSEQ. A source skill basename itself must be UTF-8 for specification comparison. Do not describe a Unix-looking string test as Windows filesystem support.

The initial reader accepts Linux ext-family/Btrfs/XFS/tmpfs/overlay filesystem magic candidates and local macOS APFS. Unknown/network/pseudo filesystems fail closed. HFS and other macOS filesystems are outside this initial reviewed subset. The list is a conservative reader eligibility policy, not proof every filesystem/version has been exercised, nor installation-backend enablement. Native CI and local QA identify the actual tested environments. Mount topology changes, malicious filesystems/kernels, privileged attackers, reparenting already-open directories outside the controlled hierarchy, arbitrary concurrent snapshot consistency and unbounded kernel I/O latency remain outside the contract. `root_is_unchanged` checks only the retained root's stamp; it is deliberately not a complete tree or pathname revalidation API.

Budgets are positive and bounded:

| Inventory budget | Default | Hard ceiling |
| --- | --- | --- |
| Entries, files and directories below root | 4096 | 65536 |
| Bytes per file | 8 MiB | 256 MiB |
| Total regular-file bytes | 64 MiB | 1 GiB |
| Relative component depth | 32 | 64 |
| Relative native path bytes | 4096 | 8192 |

SKILL.md also uses the metadata document budget. Directory names are collected only within the global entry budget and sorted before traversal. File data is streamed in bounded chunks, checking observed length and at most one extra byte at a file/total budget boundary, so a growing file cannot bypass limits. Resource bytes are hashed without retaining the whole payload; exact manifest bytes remain retained. Access-time bookkeeping is excluded from mutation stamps. No partial inventory is returned: errors report the first failing path/reason; subsequent entries are uninspected. A success never silently excludes an unsafe entry. These checks are not an atomic snapshot guarantee; later planning/apply must reopen and validate every relevant identity/digest/binding.

On Unix, record full source modes for preconditions and ordinary output intent `source_mode & 0755`. This strips privilege and group/other-write bits without granting source-denied read/execute bits. Inventory does not chmod source data or preserve ACLs, ownership, extended attributes or capabilities. Actual private staging and permission application belong to the executor. Windows now has a separately gated read-only NTFS reader described below; other unreviewed platforms return a typed unsupported result before inspection. Read-only inventory does not enable Windows planning or copying.

### Inventory regression coverage

Original owned-temp-root tests cover a minimal/resource-bearing skill, binary and executable resources, exact manifest/extension preservation, empty directories, deterministic ordering/digests, unchanged before/after trees and modes, missing/invalid manifests, Unicode paths, native non-UTF-8 capability differences, source root aliases and missing context, all configured budgets, unsafe names, links, hard links, FIFOs and sockets. Private deterministic hooks replace a final entry or directory with a symlink, replace a regular file with a FIFO after lookup, change/grow a source before reading, and replace an entry after reading. The raced FIFO test has a finite supervisor deadline. No timing-only race is claimed as proof.

## Windows read-only inventory

The Windows reader uses the retained-handle primitives reviewed in [the backend evidence](verification/windows-backend.md). It accepts only a native absolute caller-trusted directory on a fixed local drive with a locally reported NTFS volume. UNC/device roots are rejected by pure prefix policy before any open, mapped/non-fixed drives are refused, and root components are traversed with retained no-reparse handles from the drive root. Ancestor reparse aliases are deliberately unsupported on Windows, including links to another local root; ancestor traversal/read permissions are required. `GetVolumeInformationByHandleW` checks filesystem identity; `NtQueryVolumeInformationFile(FileFsDeviceInformation)` rejects remote/virtual-SMB device characteristics. Other filesystems or unavailable capability fail closed. This eligibility check is not proof of all NTFS deployment, mount or security configurations.

Descendant enumeration uses `NtQueryDirectoryFile` with one bounded SDK record per call and completion-byte validation, through a separate `ReOpenFile` cursor. Names stay native UTF-16, including unpaired surrogates in resources. Dot entries are ignored, unsafe names/reparse entries are rejected, and remaining count/depth/path/file/total/metadata budgets apply before successful inventory. Directory epochs, full native 128-bit IDs, volume identity, ordinary attribute intent, lengths and timestamps are compared around traversal/reads. File digests use the already-reviewed pure BLAKE3 implementation, now also compiled on Windows. All payloads remain inert.

Named NTFS data streams are rejected on roots, directories and files through bounded `FileStreamInfo` metadata enumeration. They are not silently omitted or copied as source security metadata. Reparse, special, multiply-linked and alternate-stream inputs return unsafe-entry refusal; native I/O codes are preserved for genuine syscall failures. Directory-link creation privileges are required in native tests and fail explicitly if missing.

On Windows, the public diagnostic `EntryStamp.inode` contains only the low 64 ID bits; `file_identity()` returns the full observed identifier, and actual equality/security revalidation retains the full native stamp privately. Unix fields/behavior are unchanged. The Windows stamp cannot be externally fabricated because of this retained private data; successful inventory construction was previously unsupported on Windows. The reported `mode`/`output_mode` is ordinary read-only intent (0444/0644 files, 0555/0755 directories), not a Unix permission/ACL equivalence or a copied Windows security descriptor. Windows times retain native FILETIME epoch values split into seconds/nanoseconds, not Unix epoch. Copy security inheritance/private staging remains a later gate.

Reproduce on Windows with `cargo test -p agent-skills-kit --test inventory --locked -- --nocapture`; required CI also runs Windows Clippy and the declared MSRV. Tests cover deterministic read-only scans, exact bytes, Unicode/spaces, unpaired surrogate resources, read-only intent, native root/descendant reparse rejection, multiply-linked and alternate stream refusal, invalid metadata/roots and entry/depth/file/total bounds. Native pass results belong to final-SHA PR QA; a macOS compilation cannot validate Windows behavior.
