## Deferred or excluded capabilities and precise gaps

- **Kiro:** Skills and Configuration disagree about effective same-name scope priority. Record the conflict; do not assert activation precedence. No documented IDE KIRO_HOME relocation is established. Legacy V2, Web/Mobile/Crew/ACP, sync/import and cloud/managed stores are not inferred. Kiro CLI V3 is an engine mode, not a package version 3.x.
- **Antigravity:** SDK, editor extensions, remote/cloud behavior and plugin-managed stores are separate from App/CLI/standalone IDE. The generic relative `.agent/skills` compatibility note does not establish a home `.agent` reader. No replacement skills-root variable is established by the reviewed configuration documentation.
- **Goose:** Skills names additional “platform-specific config directories” without concrete per-OS skills paths. Config.yaml locations and GOOSE_PATH_ROOT data/config/state relocation do not establish a replacement `.agents` skills root; alternate-profile actual discovery is untested. Mobile/ACP/remote/GDK and bundled/plugin stores are not aliases to these variants. The [AAIF migration announcement](https://goose-docs.ai/blog/2026/04/07/goose-moves-to-aaif/) establishes the canonical documentation ownership chain after the former Block landing redirect, not a persisted-path rename.
- **OpenClaw:** Nondefault state excludes home personal/compatibility skills. User scope is guarded rather than redirected into managed/shared state. Named-profile or relocated-home personal behavior is not modeled; the stricter refusal is documented in [resolution](../resolution.md). Managed/shared, Workshop, immutable personal library revisions, bundled/Custodian/plugin stores and node/remote/companion identities remain outside MVP writes. Other execution workspaces, extra/conditional readers, grouped discovery, eligibility and snapshots are not evaluated. Repository/CWD is explicitly distinct from configured agent workspace.
- **Windsurf / Devin Desktop:** The official skills URL redirects and the [product FAQ](https://devin.ai/desktop) confirms the rename. Current Cascade paths retain `.codeium/windsurf` and legacy project `.windsurf`; no pre-upgrade release parity or additional support row is fabricated. Claude-compatible readers are conditional on enabled config reading. Enterprise stores are read-only with conditional fallback and are not writable MVP scopes. Devin Local uses separate CLI discovery; cloud/ACP agents, Spaces containers and JetBrains/plugins are not Cascade aliases.
- **Zed:** External Agents and Terminal Threads own separate native skill systems. Project trust, the 50KB aggregate catalog budget, permissions and activation can exclude a copied skill. Custom search paths are unsupported in the official Skills Limitations; no `.zed/skills` or config-directory relocation is guessed. FreeBSD, web, remote identity and untested GUI/driver/ARM combinations are not validated by native library CI.

These gaps are explicit research outcomes, not tests marked as passing. Extending them requires new primary-source review and scope-specific tests; managed writes, cloud/import acquisition and post-MVP operations need separate scope authorization. A later documentation correction must preserve canonical identity and revise the relevant evidence rather than silently count a rename as another supported product.

## Verification and acceptance mapping

- Every shipped root and variant has direct resolver assertions in `tests/expanded_targets.rs`; Kiro/OpenClaw override encoding and Windows namespaces have separate integration tests. All discovery evidence arrays remain empty.
- Native temporary-root tests exercise successful copies, shared versus distinct preferred writes, canonical attribution/deduplication, exact inert bytes/resources/empty directories, unchanged retry, edited conflicts and preservation of legacy/managed reader sentinels where relevant. Kiro/OpenClaw rejection cases verify no fallback write; Zed Unicode names produce a typed host constraint before writes.
- General Unicode validation remains available to other hosts. Zed's ASCII, length, hyphen and case boundaries are tested separately from its path rules. No scripts, hooks, host processes, credentials, models or real user skill directories are used.
- Required verification includes fmt, all-target compilation, warning-denied Clippy/rustdoc, workspace and standalone consumer tests, native Linux/macOS/Windows and Linux/Windows MSRV checks, generated-matrix consistency and final-diff review. Per-final-SHA commands/results/limitations are in the separate QA Evidence comments on [#95](https://github.com/wiyco/agent-skills-kit/pull/95#issuecomment-6224840827), [#96](https://github.com/wiyco/agent-skills-kit/pull/96#issuecomment-6224923546), [#98](https://github.com/wiyco/agent-skills-kit/pull/98#issuecomment-6225024970), [#99](https://github.com/wiyco/agent-skills-kit/pull/99#issuecomment-6225108549), [#100](https://github.com/wiyco/agent-skills-kit/pull/100#issuecomment-6225230277), [#101](https://github.com/wiyco/agent-skills-kit/pull/101#issuecomment-6225299784) and the final Zed/reconciliation PR linked from Issue #20. Windows Clippy uses the development pin; Windows MSRV verifies compilation/tests/consumer, not MSRV Clippy.
- The README and generated matrix explicitly separate source/documentation review and resolver evidence from unverified real-host discovery. Native OS copy success does not establish target-host support or absolute correctness. Minimum skills versions, installed host discovery, native desktop/ARM and other filesystems remain unverified unless separately recorded.
