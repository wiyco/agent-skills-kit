# Read-only destination observations and planning

The `planner` API exposes `observe_destination(trusted_root, relative_path)` as a bounded native namespace observation and `plan_install(catalog, request)` as a conservative multi-skill preview. Neither authorizes writes. Existing directories become `Unchanged` only after full retained-handle payload comparison.

## Trust and absence

The caller explicitly chooses the root and must control its ancestor namespace under the [accepted threat model](threat-model.md). A missing root is permitted: the observation retains its closest existing ancestor and records missing components in order, without creating them. `trusted_anchor()` exposes that actual choice; `destination()` is the canonical anchor plus selected component labels. A canonical-looking string is not a containment proof, and descendant labels may alias on case/normalization-insensitive filesystems. Later planning must use opened identities as well as component boundaries.

Root parent traversal/NUL/relative paths are rejected. Strip dot/trailing separators before final-root no-follow opening. Root final aliases and all untrusted descendant symlinks, special files and regular files are refused. Ancestor aliases inside the explicitly trusted root selection can be canonicalized and are checked against the retained identity. The relative path is interpreted one component at a time, with the same portable resource-name and local-filesystem eligibility policies as source inventory. Empty relative paths observe the root itself. No payload file is opened or read. Windows implements read-only observations on fixed local NTFS drives, with all root/descendant reparse aliases refused; actual install planning/copying remain gated.

An absent component is accepted only from the native not-found result. Permission, type, I/O and unsupported-filesystem failures never turn into guessed absence. Existing directory lookups are preconditions: the opened handle must match the observed type/identity/mode/link/length before it is retained. Directory handles anchor all descendant lookup/open operations. A deterministic lookup/open swap test replaces a directory with an outside-pointing link and verifies refusal without touching the outside sentinel.

## Preconditions and limits

`DestinationSnapshot` is immutable and retains every opened directory. Its inspection methods expose requested/canonical labels, existing identity stamps, missing components and presence (`Missing` or `ExistingDirectory`). It has no public constructor for fabricated handles/preconditions. `is_current()` reopens the trusted anchor and rechecks selected bindings, directory identities/modes, and the first missing component. Unrelated additions or changes inside the final directory do not imply a namespace conflict. The full planner additionally compares existing payloads; content revalidation at execution remains mandatory.

Revalidation is a read observation, not an atomic namespace lock. It cannot prove absence until a later write, replace the native no-clobber commit, authorize adoption of a newly created parent, or protect against the threat model's excluded hostile reparent/mount/kernel cases. An executor must revalidate relevant preconditions immediately and retain operation ownership. No lockfiles, temporary files, receipts, mkdir, chmod, cleanup or environment mutations occur here. Windows retained handles deny ordinary deletion/rename of selected directories while held; they do not freeze directory contents or authorize a write.

Fixed budgets are 32 KiB of root bytes, 8 KiB of relative native path bytes, 64 relative components and 64 missing root components. Only the selected path is traversed; directory contents are not enumerated. These bounds limit retained handles/path work and are distinct from source-inventory budgets or kernel I/O timeouts. Namespace errors contain an exact path and typed reason/operation/OS code. Treat diagnostic labels as untrusted text when rendering.

## Sources and verification

Reviewed primitive sources and dependency versions remain those in [native inventory review](validation.md#native-reader-source-and-dependency-review-2026-10-16): Linux/Apple open/openat/statfs documentation, exact rustix directory/stat/open wrappers, installed macOS SDK flags, and the shared portable-name policy. Source inventory and destination observations share one internal native helper module. No host path or host override is added.

## Multi-skill previews

`InstallRequest` supplies previously validated skills, target IDs, scope, explicit context and finite `PlanLimits`. The planner rereads every selected source with the native inventory reader and rejects changed stamps, entry sets, bytes or digests. It owns the refreshed snapshots in its result; it never silently approves changed source content. These observations do not freeze a mutable tree. Execution must revalidate the approved snapshots again.

Targets are canonicalized through the catalog and sorted by ID. Unknown IDs, resolution errors and host-specific metadata constraints remain visible as unsupported requests. Each target retains reviewed rule evidence and warnings, including shared-reader exposure. A native placement is never redirected into a shared path for convenience.

Operations deduplicate by retained directory identity, or by closest existing parent identity plus exact missing components. All source/target attributions remain available. Equivalent selected payloads share an operation; different selected payloads at that location conflict. Source/source, source/destination and destination/destination containment is rejected using native ancestor identities and component boundaries. Fixed `..` traversal is used only to inspect directory ancestry, never to interpret payload names. The ancestry bound is 256 directories.

Missing destinations become `Create` only after bounded namespace and portable-name checks. Existing directories are `Unchanged` only after comparison; differences, invalid/unreadable payloads and unsafe entries become typed conflicts. Links and files also block ordinary creation. `is_applicable()` requires every request to be a problem-free create or unchanged payload. It is intent, not a permission check or a replacement for native no-clobber execution. A mixed preview can describe eligible writes while remaining inapplicable as a whole.

`intended_writes()` lists final skill roots, supporting directories/files, original-byte digests/lengths and missing parent requirements. Shared parent writes are deduplicated globally. New parents have mode 0700; payload modes use the source ordinary-mode cap `& 0755`. Private owned staging is an execution detail, not an extra persistent payload. No directory, staging file, lock, receipt or permission change is made during planning.

Whole-preview defaults/ceilings are: raw sources 32/128, raw targets 64/256, source-target combinations 128/1024, inspected entries 16384/65536, reread bytes 256 MiB/1 GiB, recorded path bytes 16 MiB/64 MiB, intended entries 16384/65536. Per-inventory limits also apply, tightened to the remaining entry/byte budget. Zero or excessive settings fail; budget/source/structural failures return no partial plan. Directory collision scans consume the entry budget. Windows fails closed before inspection.

## Portable collision policy and dependency review (2026-10-16)

Names are preserved exactly. For collision rejection only, Unicode components use canonical decomposition, full default case folding and canonical decomposition again, following [Unicode canonical caseless matching, section 3.13](https://www.unicode.org/versions/Unicode18.0.0/core-spec/chapter-3/). Raw non-UTF-8 Unix names use byte-preserving ASCII folding. Payload collisions, aliases of the first missing native component and conflicting future intermediate component spellings are rejected. This conservative portable policy is not an emulation of every filesystem collation/version, nor proof that all possible aliases are detected. Native identity and eventual exclusive commit remain mandatory. The archived [Apple APFS FAQ](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/APFS_Guide/FAQ/FAQ.html) describes historical case/normalization behavior; its Unicode-version statement is not treated as evidence for current APFS implementations.

Unix-only additions avoid a hand-maintained Unicode mapping: [unicode-normalization 0.1.25](https://github.com/unicode-rs/unicode-normalization) (MIT OR Apache-2.0, declared MSRV 1.36, Unicode 17.0 tables), [caseless 0.2.2](https://github.com/unicode-rs/rust-caseless) (MIT, no declared MSRV, Unicode 16.0 folding tables), and normalization's transitive [tinyvec 1.13.3](https://github.com/Lokathor/tinyvec) (Zlib OR Apache-2.0 OR MIT, no declared MSRV). Exact locked manifests and algorithm/table sources were reviewed. All three repositories are non-archived; caseless's last push was 2024-12-30, normalization's 2026-09-18, tinyvec's 2026-09-16. Caseless is mature but less recently updated. Different table versions mean this is explicitly not complete Unicode 18 folding coverage. The locked graph must pass actual Rust 1.85 CI; undeclared MSRVs are not inferred from age. Dependency/advisory automation remains later work.

Native tests cover ordering, core placements, attribution, physical parent aliases, conflicting/equivalent sources, stale manifests, overlap, intermediate case aliases, limits and before/after byte/mode tree equality. Linux additionally creates payload case/normalization aliases that cannot coexist on the local default APFS volume. Pure Unicode key tests run on both native backends. Host discovery, privileged mounts, arbitrary filesystem collation versions, power-loss behavior and copy execution are not validated by these tests.

Original temporary-root tests exercise missing parents/root, existing identities, read-only before/after trees, explicit absence, selected replacement and permission changes, tolerated unrelated changes, Unicode/native path identity, root/descendant aliases and non-directories, traversal and fixed budgets. All existing source inventory/parser/adapter regressions also apply. Linux/macOS require native success evidence; Windows tests demonstrate refusal, not installation support. Actual host loading, unsupported filesystem candidates, destination payload comparison, case/normalization collisions, overlap, execution and cleanup are not established by this layer.

## Existing payload equality

Comparison uses the already retained final directory handle. Diagnostic path labels are never reopened to traverse its payload. The shared inventory walker checks every entry and reads every regular file under the same no-follow, hard-link, filesystem, depth and byte limits as source validation. It requires valid metadata and the exact requested skill directory spelling; a case-insensitive lookup of a differently spelled directory does not establish equality. A deterministic unit test swaps the diagnostic pathname for an outside-pointing link and proves that inspection still reads the retained original directory.

Equality requires the complete sorted relative entry set and types, file lengths/BLAKE3 digests, original manifest bytes, empty directories and intended modes. Existing ordinary and privilege bits (`& 07777`) must exactly equal the source's intended capped mode (`& 0755`), including the root. Ownership, ACLs, extended attributes and timestamps are not payload equality properties; ordinary modes alone do not characterize effective access. No metadata is regenerated or repaired. Existing content is never adopted as a new source or overwritten.

An unchanged row retains its complete inspected `ValidatedSkill` as execution preconditions and has no intended writes. A later content change still requires executor rejection; a retained handle is not a snapshot or lock. Native namespace preconditions are rechecked before returning the preview. Source and destination inventories remain bounded observations, not an atomic cross-tree transaction.

Existing inspection failures reserve their whole allowed byte/entry budget, since they may have consumed it before failing. This conservative accounting can cause a later destination to exhaust the whole-preview budget instead of returning a partial preview. Successful comparisons charge actual bytes/entries. The native reader may probe one byte beyond a failed byte limit to detect growth; it never retains an unbounded resource. Windows install planning remains unsupported before inspection; its separate namespace observation and source inventory APIs are read-only.

Regression cases cover unchanged full payloads, modified resource bytes, extra/missing files, missing empty directories, root/file modes, retained setuid bits, symlinks, hard links, invalid manifests and existing case aliases. On macOS sandboxed chmod can silently strip setuid bits; the fixture asserts the bit actually exists and requires the scoped unsandboxed test run. A stripped-bit run is not counted as privilege-bit coverage. Native CI and bounded-budget tests remain required on the final revision.


## Windows namespace security preconditions

Windows observations use the reviewed retained-handle reader and local-drive/NTFS eligibility policy. Missing roots retain the closest existing verified prefix; no parent is created. Relative components are bounded and validated, selected directories retain no-delete-sharing handles, and identity comparisons use all 128 file-ID bits. An ordinary competing entry may still appear at a missing component; `is_current()` detects it but cannot replace exclusive commit.

Each retained directory additionally stores bounded owner/group/DACL descriptor bytes read through `GetSecurityInfo`. Revalidation compares those preconditions and ordinary read-only intent while ignoring unrelated directory-entry epochs. ACL-only inheritance changes therefore invalidate the observation even if native identity and DOS flags stay unchanged. SACL/audit/integrity policy is not captured by this API, and these observations alone do not approve a Windows executor security policy. No existing directory's ACL or permissions are changed by the library.

Reproduce native namespace scenarios with `cargo test -p agent-skills-kit --test namespace --locked -- --nocapture` on Windows. Fixtures cover missing roots/appearance, Unicode/spaces, full identity, unrelated additions, ordinary rename denial while held, read-only intent, reparse/traversal/stream/device refusal and a real ACL-inheritance toggle with restoration on an owned empty directory. Windows backend completion, private-stage permissions and copy/partial/race evidence remain required for ASK-012.
