# Permanent-removal API development

Status: read-only planning/approval foundation for #113. There is no destructive apply backend or CLI delete command in this layer. Do not treat it as implemented uninstall or publish the alpha before native removal and CLI integration pass the complete [ADR 0009](adr/0009-permanent-removal.md) gates.

`removal::plan_removal` consumes a successful `SkillListing`, a zero-based location index, exact native skill basename, explicit `InstallContext` and `RemovalLimits`. It requires a complete present non-alias root/valid skill, rechecks the retained container and re-inspects the selected payload through the shared native no-follow inventory. Full root/entry stamps and original metadata bytes must still match discovery. A catalog/context resolution must identify that physical source container, so a mismatched context cannot silently change the preview.

`RemovalPlan` has private immutable fields and getters for canonical source target/scope, exact native path/name, selected root stamp, all descendant entries, original metadata bytes, total regular-file bytes, known readers and unresolved reader diagnostics. The selected root is an intended removal in addition to every returned descendant. Existing/unmanaged valid skills can be explicitly selected; no installed-by-this-program ownership is inferred. Unsafe/invalid metadata and incomplete listings are refused rather than gaining deletion authority.

Reader impact resolves every catalog target's declared scopes using only the supplied context and observes native/compatibility containers through the same explicit-anchor namespace walker. Matches use full physical container identity; native/read roles and unexpanded ancestor traversal are distinguished. Missing containers cannot currently alias the source. Unsupported/unverified/configuration-required targets, missing context, unsafe/unreadable locations and unexpanded ancestor uncertainty remain explicit unresolved evidence. This is catalog-known placement impact, not exhaustive host visibility or actual loading. Reader snapshots are observations, not atomic multi-root state.

Defaults/ceilings are 256/1024 catalog targets and 1024/4096 resolved location observations, plus the existing complete inventory limits. Fingerprint encoding streams into BLAKE3 with an 8 MiB ceiling and fails explicitly on excess. It includes an operation/version domain, catalog content, exact lossless native paths, root/container and descendant stamps, file digests, original metadata bytes, source target/scope/bytes and reader/unknown evidence. It is deterministic for unchanged observations with the same version/catalog/context, and intentionally invalidated by changed preconditions. It is not a secret, malware review, persistent identifier or ownership credential; representation changes between builds/versions are allowed.

`approve_permanent_removal` consumes the complete plan and requires its exact `confirmation_token`. This is an explicit library call to be made only after the caller presents every intended entry/known reader, warns that deletion is permanent with no undo, and requires stopped skill writers and controlled roots/ancestors. A generic copy approval or serialized receipt does not construct an `ApprovedRemoval`; neither type is deserializable. Approval itself writes nothing. Its wrapper exposes the exact preview for later native application, which must independently revalidate and accurately report all partial state.

The consumed listing's selected payload handles are released rather than retained inside the plan. Only the container namespace is retained. Independent clones/other readers can still prevent Windows DELETE access; future apply must report actual sharing refusal without force-closing handles or weakening no-follow semantics. `namespace_is_current` checks container bindings only and never claims to freeze payload contents. Planning/approval performs no staging, locks, chmod, environment reads, network access or execution of skill contents.

Reproduction: `cargo test -p agent-skills-kit --test removal_plan --locked`. Owned inert native fixtures cover core targets and user/project scopes; every payload entry/root and shared-reader roles; deterministic fingerprints and changed contents; wrong confirmations; stale/invalid/missing/wrong-context selections; target/location limits; no stage creation, deletion or changed source bytes. Linux/macOS/Windows CI is required for the final revision. Actual removal, permission/race/partial/interruption behavior and operation-specific CLI confirmation remain unimplemented in this foundation.
