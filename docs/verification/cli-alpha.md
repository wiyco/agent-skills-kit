# Experimental CLI alpha candidate

Status: preparation under #114, dependent on #112/#113 and final native QA. Proposed tag/version: `v0.1.0-alpha.1` / `0.1.0-alpha.1`. This document does not claim an existing release or waive outstanding human publication gates.

The maintainer authorized an experimental GitHub CLI Pre-release after tool-first existing-skill listing, cross-agent copying and explicitly confirmed permanent deletion are implemented and verified on native Linux/macOS/Windows. Both Cargo packages remain `publish = false`; the library is compiled directly into the CLI and is not published independently. This is the specifically authorized lifecycle slice, not blanket M5 authorization. Stable release, crates.io, Homebrew/winget submissions, reporting-service activation and repository/Project visibility changes are excluded.

## Build and export

Required PR CI runs the fresh native bundle rehearsal on Linux x86_64 GNU, macOS Apple Silicon and Windows x86_64 MSVC. The helper clones the exact committed candidate without hooks/hardlinks, creates a fresh build directory, runs optimized workspace tests and builds a native executable using the committed Rust pin. Cargo strip-tool inference is disabled. The macOS bundle is processed with the existing Apple SDK `strip -S` to remove debug/STABS absolute toolchain archive paths; MSVC uses `/PDBALTPATH:agent-skills-kit.pdb` rather than embedding the build PDB location. No strip utility is installed or guessed. The final processed binary is hashed and exercised, and known absolute home/build/cache prefixes are checked in UTF-8/UTF-16 forms before packaging. This bounded regression check is not an independent privacy/secrets audit. It preserves project and dependency licenses/notices, records locked components and checksums, builds a bounded regular-file archive, checks its SHA-256 and safely unpacks/compares every file. It never promotes a PR build cache.

The actual unpacked executable is copied to an isolated bin directory and checked for exact version/hash/help. Original owned fixtures then exercise 13 scripted scenarios: list existing; copy approval-required, dry-run, approved and unchanged; deletion preview, dry-run, generic-yes refusal, incorrect/stale fingerprint refusal, fresh preview, approved permanent removal and list-after-removal. Verify complete contents/reader preview, all removed outcomes, no payload/enclosure remnants, unchanged independent copies and an unrelated sentinel. No skill script, real agent tool, home override, credential or model API runs. The fixture is removed afterward. These checks demonstrate this CLI/backend on the measured runner, not actual agent loading, every terminal or arbitrary filesystems.

Default PR rehearsal deletes all bundles and uploads nothing. `python -B .github/scripts/rehearse-binary.py --export-alpha <new-external-directory>` additionally exports only the verified archive, its `.sha256` file and `build-evidence-<target>.json`. It refuses non-alpha versions, changed archives, checkout destinations and existing output directories. Export is preparation, not automatic release creation.

The manually dispatched `Experimental alpha bundles` workflow accepts the exact full SHA of the selected reviewed ref and uses read-only repository permissions, no persisted checkout credentials or promoted build cache. Each native runner fetches the locked dependencies and builds fresh. The default `export_artifacts=false` verification-only dispatch uploads nothing and can validate a reviewed feature branch before merge; private runner exports are discarded when the job ends. Public artifact export requires the exact current `main` SHA. Only an explicitly enabled checked export is uploaded as a run-specific Actions artifact with seven-day retention. **Set `export_artifacts=true` only after the maintainer resolves the applicable publication gates below**, because public-repository Actions artifacts can be downloaded by authenticated users. A manual dispatch is not an independent review or a protected publishing environment. Runner-specific `CARGO_HOME` is set only on fetch/build steps, where the `runner` expression context is available; job-level environment expressions cannot use it. The workflow has no release-writing token, OIDC, signing credential, crate publisher or automatic release step.

The pinned official [upload-artifact action metadata](https://github.com/actions/upload-artifact/blob/cf430e030ddbb5b0abf93d22962f4752f3646cd9/action.yml) and [usage/limitations](https://github.com/actions/upload-artifact/blob/cf430e030ddbb5b0abf93d22962f4752f3646cd9/README.md) were reviewed on 2026-10-18 JST: Node 24, fail on missing files, immutable default/no overwrite, hidden-file exclusion and artifact digest. Actions artifact wrapper hashes are separate from the native archive SHA-256. No third-party download action is added; the maintainer can retrieve the exact successful run with the installed GitHub CLI.

## Limits to communicate

- WIP/experimental, owned temporary fixtures only; no production or real-store readiness, stability or support/SLA promise.
- Permanent deletion has no undo or secure-erasure guarantee. Full contents/shared-reader preview, operation-specific confirmation, controlled ancestors and stopped writers are required. Partial/uncertain outcomes are retained; diagnostic enclosure names are never cleanup authority.
- Native measured ABIs only. Windows Server/x64 NTFS evidence does not validate Windows 11/ARM, junction traversal, network/FAT filesystems or every privilege configuration. macOS ARM/APFS does not validate Intel macOS. Linux GNU runner builds are not portable-musl or universal-glibc promises; record actual runtime baselines in evidence.
- Unsigned/not notarized; no certified SBOM, provenance attestation, auto-updater, installer, secure erasure, power-loss durability or global rollback. Gatekeeper/SmartScreen/quarantine and other runtime policy are not validated by CI smoke tests.
- Confidential security/conduct/alternate/appeal routes remain unavailable unless the maintainer actually establishes them; do not disclose sensitive details in public Issues/PRs/Projects. Opening public contribution intake remains gated.
- Future stable distribution can separately evaluate GitHub binaries, an owned Homebrew tap, winget manifests and library crates.io publication. None is an existing or authorized external package-manager channel in this alpha change.

## Binary path privacy regression

The initial private macOS candidate retained absolute standard-library archive paths in Mach-O debug/STABS symbols despite compiler prefix remapping. It was rejected for distribution. The existing Apple SDK `strip -S` removes those debug symbols; the processed executable must still pass exact version/hash and the complete native manager smoke flow. Record the processing operation/SDK version in the inventory and evidence. The Windows link option changes only the embedded PDB reference, not the build PDB destination; PDBs are not bundled. Linux retains its symbol table, subject to the same bounded path scan. No signing/notarization, obfuscation or complete privacy proof is implied.

Primary sources reviewed 2026-10-18 JST: [Apple cctools strip manual](https://github.com/apple-oss-distributions/cctools/blob/main/man/strip.1), also present in the installed Command Line Tools man page; [Microsoft /PDBALTPATH](https://learn.microsoft.com/en-us/cpp/build/reference/pdbaltpath-use-alternate-pdb-path?view=msvc-170); [Rust linker-argument and strip semantics](https://doc.rust-lang.org/rustc/codegen-options/index.html#link-arg). Native execution after processing, not documentation alone, establishes the measured recipe.

The initial manual workflow definition was rejected by GitHub after merge because it referenced `runner.temp` in job-level `env`. That context is unavailable there under the [official availability table](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#context-availability). The follow-up moves it to step-level `env` and adds a default no-upload verification mode so the actual manual workflow can be tested without public binary distribution. Required Rust CI alone did not validate an untriggered workflow definition; final evidence must distinguish definition registration, actual verification-only execution and still-pending public export.
