# ASK-028: Design a separate remote skill acquisition layer

## Goal

Add remote acquisition only after the local installer has a stable trust boundary.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This repository is private during development and is intended for a future English-language OSS release.

## Scope

- Keep Git/URL/archive acquisition separate from destination resolution and local copy execution.
- Pin immutable revisions where possible and record source provenance/integrity.
- Defend against archive traversal, decompression/resource abuse, unsafe redirects, credential leaks, and untrusted Git hooks.
- Do not execute fetched skill code or assume a public repository is trustworthy.

## Acceptance criteria

- [ ] The fetch layer returns a bounded validated local source to the existing installer.
- [ ] Network/credential behavior is explicit and independently testable.
- [ ] Integrity and trust claims are accurately scoped.
- [ ] Failures do not leave partially installed skills.

## Verification

- Use local fake servers and malicious archive fixtures.
- Test immutable ref handling and credential redaction.
- Require a fresh threat-model review.

## Non-goals

Do not expand this issue into unrelated roadmap work.

## Handoff

Open a focused PR with `Closes #<actual-issue-number>`. Report commands actually run, results, untested platforms, and any remaining risks. Do not merge or publish without maintainer approval.
