# ASK-002: Finalize project naming, licensing, and contributor conventions

## Goal

Prepare the repository for future public collaboration without publishing it now.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This is a WIP, not-ready-for-use English-language OSS source preview, not a supported or published library/CLI. Source visibility is separate from crate and binary publication; see `docs/public-readiness.md` and `docs/release.md`.

## Scope

- Check proposed repository, crate, and executable names for collisions and confusing similarity; names in this plan are not reservations.
- Propose MIT OR Apache-2.0 to the maintainer; record approval before adding license texts or changing package metadata.
- Complete CONTRIBUTING, a code of conduct with a real reporting route, SECURITY, and issue/PR templates in English.
- Document attribution rules for third-party registry data, source snippets, and test fixtures. Use original small fixtures by default.
- Compare existing Rust and non-Rust installers using current primary sources; record adopt-versus-build decisions and license compatibility instead of trusting earlier library claims.

## Acceptance criteria

- [ ] Approved names and license choice are recorded in an ADR; unresolved decisions remain explicit blockers for publication.
- [ ] No invented maintainer email, sponsorship account, badges, adoption statistics, or release claims appear.
- [ ] All repo-facing content is English and omits private conversation details.
- [ ] Third-party material has traceable provenance and allowed reuse.

## Verification

- Review proposed names against the relevant registries at decision time.
- Check relative documentation links and templates.
- Record maintainer approval for legal and branding decisions.

## Non-goals

Do not reserve crates by publishing empty packages. Do not change visibility, invite collaborators, or publish a release.

## Primary references

- https://doc.rust-lang.org/cargo/reference/publishing.html

## Handoff

Open a focused PR with `Closes #<actual-issue-number>`. Report commands actually run, results, untested platforms, and any remaining risks. Do not merge or publish without maintainer approval.
