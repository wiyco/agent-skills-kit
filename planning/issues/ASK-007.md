# ASK-007: Implement skill validation and bounded source inventory

## Goal

Validate a local skill directory and produce a safe inventory without executing its content.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This is a WIP, not-ready-for-use English-language OSS source preview, not a supported or published library/CLI. Source visibility is separate from crate and binary publication; see `docs/public-readiness.md` and `docs/release.md`.

## Scope

- Validate SKILL.md frontmatter according to the current Agent Skills specification, preserving unknown extension fields.
- Distinguish general specification validation from target-specific constraints.
- Inventory files deterministically with configurable file-count, per-file, total-size, and nesting limits.
- Reject unsafe file types, traversal-like names, and source symlinks/reparse points under the MVP policy.
- Preserve supporting assets and executable-bit intent under a documented permission policy.

## Acceptance criteria

- [ ] Missing or invalid metadata produces typed diagnostics with useful locations.
- [ ] The skill name cannot inject a path, conflict with reserved OS names, or escape the destination root.
- [ ] Parser/inventory processing never runs scripts, hooks, embedded commands, or SKILL.md instructions.
- [ ] Unknown frontmatter is not destroyed by installation.
- [ ] Limits prevent unbounded resource use and all excluded/rejected entries are reported.

## Verification

- Test valid minimal and resource-bearing skills, malformed YAML, CRLF/BOM policy, large inputs, invalid names, symlinks, and special files.
- Add original small malicious-looking fixtures as inert data.
- Run tests entirely inside temporary roots.
