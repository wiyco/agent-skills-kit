# ASK-009: Implement read-only install plans and destination deduplication

## Goal

Produce a deterministic preview that is sufficient for CLI confirmation and library consumers.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This is a WIP, not-ready-for-use English-language OSS source preview, not a supported or published library/CLI. Source visibility is separate from crate and binary publication; see `docs/public-readiness.md` and `docs/release.md`.

## Scope

- Plan one or more validated local skills for selected targets and an explicit scope.
- Represent create, unchanged, conflict, and unsupported outcomes, plus per-target warnings and evidence.
- Deduplicate genuinely identical destinations while retaining target attribution; reject overlapping roots and source/destination recursion.
- Record source inventory/digests and destination preconditions needed to detect stale plans.
- Keep all host-specific path knowledge out of CLI code.

## Acceptance criteria

- [ ] Planning performs zero filesystem writes, including no mkdir, receipt, lock, or temp-file creation.
- [ ] Ordering is stable and independent of hash-map iteration.
- [ ] Different existing content fails by default; byte-identical content can be reported as unchanged only after comparison.
- [ ] Shared-location exposure is visible and cannot be described as target isolation.
- [ ] A plan identifies every intended write and all requested targets, even after deduplication.

## Verification

- Snapshot plans for core-target combinations.
- Prove read-only behavior by comparing filesystem trees before and after.
- Test same-path aliases, case-collision scenarios, ancestor/descendant roots, and stale source manifests.
