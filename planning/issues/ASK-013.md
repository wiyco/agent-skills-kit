# ASK-013: Stabilize the reusable API and add external consumer examples

## Goal

Prove the library is useful without the bundled CLI.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This is a WIP, not-ready-for-use English-language OSS source preview, not a supported or published library/CLI. Source visibility is separate from crate and binary publication; see `docs/public-readiness.md` and `docs/release.md`.

## Scope

- Expose registry lookup, explicit context resolution, validation, plan, and apply as separate reusable operations.
- Provide typed errors, extensible target registration, and versioned serializable reports where needed.
- Keep terminal prompts, process exit, CLI argument parsing, network acquisition, and global configuration out of the library.
- Add rustdoc and a minimal external consumer package using the public API.
- Review public types for semver evolution and avoid unnecessary async/runtime dependencies.

## Acceptance criteria

- [ ] An independent Rust package can select core targets, preview, and install a local fixture via public APIs.
- [ ] Custom targets require no CLI changes or library fork.
- [ ] The library does not print or exit the process on errors.
- [ ] Documented examples compile and unsafe operations have reviewed justification.
- [ ] The planned package contents include all catalog data and exclude sensitive/local files.

## Verification

- Run rustdoc/doctests and an external-consumer integration check.
- Test unknown targets, unsupported scopes, custom entries, and versioned report parsing.
- Inspect cargo package --list during packaging readiness.

## Non-goals

Do not expand this issue into unrelated roadmap work.
