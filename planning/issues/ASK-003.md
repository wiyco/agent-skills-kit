# ASK-003: Establish native OS CI and a measured MSRV policy

## Goal

Make filesystem behavior testable on Linux, macOS, and Windows from the start.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This repository is private during development and is intended for a future English-language OSS release.

## Scope

- Create GitHub Actions jobs for pinned-toolchain tests on native Ubuntu, macOS, and Windows runners.
- Run formatting, Clippy, documentation checks, and all intended features; add no-default-features coverage if features exist.
- Select a realistic library MSRV by testing the code and dependency graph; add a separate MSRV job and latest-stable compatibility job.
- Pin third-party actions to verified full commit SHAs, retain release comments, and configure an update mechanism.
- Use read-only default permissions, bounded job timeouts, cancellation of superseded runs, and a dependency-aware Rust cache.

## Acceptance criteria

- [ ] PR and main-branch CI run without secrets or AI provider accounts.
- [ ] MSRV is declared only after the MSRV job succeeds and is documented separately from the dev pin.
- [ ] Tests use temporary directories and injected context, not the runner home.
- [ ] No privileged pull_request_target job executes untrusted PR code.
- [ ] No fabricated action tags or SHAs are committed.

## Verification

- Open a test PR and inspect all native jobs.
- Verify formatting and Clippy failures fail CI.
- Verify cache keys include the toolchain, OS, and lockfile.

## Non-goals

Do not expand this issue into unrelated roadmap work.
