# ASK-017: Verify Cline, Roo Code, and Kilo Code variants

## Goal

Add evidence-backed editor/CLI variants of Cline, Roo Code, and Kilo Code without inheriting assumed paths between forks.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This repository is private during development and is intended for a future English-language OSS release.

## Scope

- For each named candidate, verify official documentation first, follow redirects, and record the exact product/variant and applicable version.
- Implement only documented copy-installable scope/platform combinations; retain unverified or import-only cases as explicit research outcomes.
- Add preferred-write/read-discovery distinctions, overrides, reserved names, and compatibility behavior to the evidence record.
- Add resolver fixtures and regenerate supported-target documentation. No path may be inferred from a brand name.

## Acceptance criteria

- [ ] Each candidate has a documented disposition: implemented with evidence/tests, deferred with a precise gap, or unsupported with a source.
- [ ] Every shipped path rule has a primary source, accessed date, and passing resolver tests for the supported platforms.
- [ ] IDE, CLI, cloud, fork, and renamed variants are not conflated or double-counted as proof of support.
- [ ] The README distinguishes documented resolution from real-host discovery testing.

## Verification

- Run catalog validation and target-specific resolver tests.
- Verify aliases and shared-path deduplication with existing targets.
- Record any host/version/OS not exercised; do not claim an unrun smoke test.

## Non-goals

Do not expand this issue into unrelated roadmap work.
