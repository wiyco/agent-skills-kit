# ASK-023: Add dependency, license, and CI supply-chain checks

## Goal

Reduce publication risk without adding production dependencies or privileged CI.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This is a WIP, not-ready-for-use English-language OSS source preview, not a supported or published library/CLI. Source visibility is separate from crate and binary publication; see `docs/public-readiness.md` and `docs/release.md`.

## Scope

- Choose and configure maintained Rust advisory/license checking tooling after reviewing current official docs.
- Add dependency/action update PRs, full-SHA action pinning, and a reviewed license policy.
- Review artifact and cache trust boundaries, lockfile policy, and generated package contents.
- Document SBOM/provenance expectations and secret-scanning availability without inventing platform entitlements.

## Acceptance criteria

- [ ] Dependency and license violations are visible in CI with documented exception handling.
- [ ] No broad write token or long-lived publishing secret is available to PR jobs.
- [ ] Any exception has an owner, reason, and review date.
- [ ] Current direct dependencies are justified for the library rather than inherited from the CLI.

## Verification

- Test the checks with a controlled failing configuration.
- Review action pins against upstream repositories.
- Inspect dependency trees and packaged files.

## Non-goals

Do not expand this issue into unrelated roadmap work.

## Primary references

- https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions
- https://doc.rust-lang.org/cargo/reference/publishing.html

## Handoff

Open a focused PR with `Closes #<actual-issue-number>`. Report commands actually run, results, untested platforms, and any remaining risks. Do not merge or publish without maintainer approval.
