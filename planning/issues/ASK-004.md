# ASK-004: Specify a versioned target catalog and evidence model

## Goal

Define reusable target metadata that records what is known, not a table of guessed directories.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This is a WIP, not-ready-for-use English-language OSS source preview, not a supported or published library/CLI. Source visibility is separate from crate and binary publication; see `docs/public-readiness.md` and `docs/release.md`.

## Scope

- Model stable target IDs, aliases, product variants, supported scopes, platform constraints, preferred write destinations, and alternative read/discovery locations.
- Represent path bases and environment overrides as explicit rules; do not hide interpretation inside arbitrary strings.
- Record official URL, section, accessed date, tool/version applicability, and documented limitations per rule.
- Keep documentation verification, resolver test coverage, and real-host smoke testing as separate evidence dimensions.
- Represent unsupported, import-only, configuration-dependent, and unverified cases explicitly.

## Acceptance criteria

- [ ] Schema examples cover Codex, Claude Code, OpenCode, an XDG-dependent target, and an application workspace target.
- [ ] A missing path is not interpreted as a default path.
- [ ] The schema can evolve without silently changing the meaning of existing IDs.
- [ ] A documented preferred write destination is distinct from every location a host can read.
- [ ] The bundled catalog is deterministic and requires no network access at install time.

## Verification

- Add schema validation and duplicate-ID/alias tests.
- Test malformed path rules, missing evidence, unknown scopes, and variant collisions.
- Add a small reviewed ADR for schema versioning.
