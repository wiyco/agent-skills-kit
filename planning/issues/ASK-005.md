# ASK-005: Implement deterministic scope and environment resolution

## Goal

Resolve destinations from explicit caller context without mutating process state or guessing host behavior.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This repository is private during development and is intended for a future English-language OSS release.

## Scope

- Accept explicit project root, user home, OS/platform, and relevant environment/config overrides as input.
- Use PathBuf/OsString where appropriate; avoid UTF-8-only path assumptions.
- Require a project root for project scope; separate application workspace roots from Git project roots.
- Return destination provenance and warnings along with resolved paths.
- Treat unsupported scope/platform and missing context as typed errors, not fallbacks.

## Acceptance criteria

- [ ] Library resolution does not read mutable global environment implicitly or change CWD/HOME.
- [ ] Project and user scopes work with nonexistent destination directories.
- [ ] Windows drive/UNC handling, relative overrides, empty values, and unresolved home contexts have explicit semantics.
- [ ] XDG and host-specific variables are honored only for adapters with evidence supporting them.
- [ ] Resolution never creates directories.

## Verification

- Run table-driven resolver tests on all three native OSes.
- Cover spaces, Unicode, worktrees, nested CWDs, and missing roots.
- Test that a generic OS-directory helper cannot override host-documented paths.
