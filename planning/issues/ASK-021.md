# ASK-021: Add ongoing host discovery and catalog drift review

## Goal

Keep the catalog open to recently launched tools without trading correctness for a support count.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This repository is private during development and is intended for a future English-language OSS release.

## Scope

- Create a candidate intake workflow using official announcements, release notes, docs, and official repositories.
- Record discovery date, actual launch/release date when established, product identity, and evidence gaps; do not call every candidate new or trending.
- Review the most recent 180 days during each explicit discovery task, then check adjacent tools such as Warp, Augment, Continue, Replit, and Trae.
- Use third-party installer catalogs only to discover candidates; verify every adopted rule with host-owned sources.
- Add a manually triggered or low-frequency CI report for stale evidence and broken URLs, with human review before catalog changes.

## Acceptance criteria

- [ ] New targets can be proposed using an evidence-oriented issue template.
- [ ] Reachable URLs are not treated as proof that paths remain correct.
- [ ] No schedule automatically rewrites adapters or executes downloaded skills.
- [ ] Reports deduplicate forks/renames and separately track unsupported or web-only products.
- [ ] A missing source produces a tracked gap instead of a guessed path.

## Verification

- Test stale-date detection and redirect/error reporting with fixtures.
- Run one documented discovery review and record its bounded scope and results.
- Ensure online drift checks are separate from offline unit tests.

## Non-goals

Do not expand this issue into unrelated roadmap work.

Open a focused PR with `Closes #<actual-issue-number>`. Report commands actually run, results, untested platforms, and any remaining risks. Do not merge or publish without maintainer approval.
