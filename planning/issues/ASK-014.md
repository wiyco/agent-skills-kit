# ASK-014: Implement the non-interactive CLI using the library

## Goal

Offer stable automation-friendly commands before adding prompts.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This repository is private during development and is intended for a future English-language OSS release.

## Scope

- Implement targets list/show, validate, plan, and install commands; provisional executable name is skillctl.
- Support repeated target selection, explicit project/user scope, explicit project root, dry-run, and structured JSON output.
- Use library validation/resolution/planning/application exclusively; do not duplicate path tables.
- Specify error codes, stdout/stderr separation, cancellation, and non-TTY behavior.
- Make --yes mean approval of a displayed/derived plan, never force overwrite or permission bypass.

## Acceptance criteria

- [ ] A script can install a fixture into the selected target directories without interactive prompts.
- [ ] JSON has a documented schema/version and contains no terminal escape sequences.
- [ ] Invalid targets/scopes fail before writes; no non-TTY prompt can hang CI.
- [ ] A path override, if included, is an advanced explicit option and not the definition of target selection.
- [ ] The CLI explains cross-host discoverability for shared locations.

## Verification

- Add CLI integration/snapshot tests with temporary roots.
- Test exit codes, redirected input, --help, --version, dry-run, --yes, and conflicting flags.
- Verify parity between library and CLI plans.

## Non-goals

Do not expand this issue into unrelated roadmap work.

## Handoff

Open a focused PR with `Closes #<actual-issue-number>`. Report commands actually run, results, untested platforms, and any remaining risks. Do not merge or publish without maintainer approval.
