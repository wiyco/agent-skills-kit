# ASK-001: Bootstrap the Cargo workspace and proto-compatible toolchain

## Goal

Create the smallest reproducible Rust workspace for a library-first installer and its CLI.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This is a WIP, not-ready-for-use English-language OSS source preview, not a supported or published library/CLI. Source visibility is separate from crate and binary publication; see `docs/public-readiness.md` and `docs/release.md`.

## Scope

- Start with two workspace members: a public-library candidate and a thin CLI. Names are provisional until ASK-002.
- Verify an available stable Rust release from the Rust project, pin its exact version in `rust-toolchain.toml`, and install rustfmt and Clippy.
- Use `rust-toolchain.toml` as the Rust version source of truth. Preserve proto usage for other tools; do not require a duplicate Rust pin in `.prototools`.
- Use Edition 2024 if supported by the chosen policy; explicitly set the virtual-workspace resolver. Commit Cargo.lock.
- Keep `publish = false` for all packages until a separately approved release change. Keep Node, pnpm, Docker, moon, and Turbo out of the Rust build path.

## Acceptance criteria

- [ ] A fresh checkout can run cargo check/test on the library and CLI skeletons.
- [ ] The active rustc version matches the committed pin; docs explain the proto/rustup boundary and Cargo PATH requirement.
- [ ] Toolchain pin and MSRV are treated separately; no untested MSRV claim is published.
- [ ] No speculative Rust or GitHub Action version is copied from prior discussion.
- [ ] Cargo.lock and repository-local test fixtures are tracked.

## Verification

- Run cargo fmt --all -- --check, cargo check --workspace --locked, and cargo test --workspace --locked.
- Record rustc -Vv, cargo -V, and rustup show active-toolchain.
- Check the documented setup both with proto present and with plain rustup.
