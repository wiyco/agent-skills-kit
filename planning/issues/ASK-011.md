# ASK-011: Add idempotency, installation receipts, and recovery diagnostics

## Goal

Make repeat runs and partial failures understandable without enabling destructive lifecycle operations.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This repository is private during development and is intended for a future English-language OSS release.

## Scope

- Return a versioned receipt containing operation ID, target IDs, content digests, installed paths, and outcomes.
- Make persistent receipt storage explicit and caller-controlled; do not modify the installed skill content or an undocumented home state directory.
- Recognize identical existing installations as no-ops and report unmanaged conflicts clearly.
- Document concurrent-run behavior and recovery of owned staging remnants.
- Avoid logging sensitive absolute paths by default in telemetry; add no telemetry service.

## Acceptance criteria

- [ ] Repeating the same request makes no content changes after success.
- [ ] Receipts never imply ownership of preexisting unmanaged files.
- [ ] Failure reports distinguish succeeded, unchanged, failed, and not-attempted targets.
- [ ] Retries preserve unrelated and manually edited content.
- [ ] No promise of cross-target rollback is made.

## Verification

- Test reruns, partially completed batches, stale receipts, and changed content.
- Validate receipt schema versions and corrupt receipt handling.
- Check cleanup identity before deletion.

## Non-goals

Do not expand this issue into unrelated roadmap work.

## Handoff

Open a focused PR with `Closes #<actual-issue-number>`. Report commands actually run, results, untested platforms, and any remaining risks. Do not merge or publish without maintainer approval.
