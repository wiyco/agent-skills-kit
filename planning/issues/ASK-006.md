# ASK-006: Verify and implement Codex, Claude Code, and OpenCode targets

## Goal

Deliver the three explicitly requested core hosts with auditable path rules.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This is a WIP, not-ready-for-use English-language OSS source preview, not a supported or published library/CLI. Source visibility is separate from crate and binary publication; see `docs/public-readiness.md` and `docs/release.md`.

## Scope

- Re-read the current official skills and configuration documentation before coding; use the seed notes only as a starting point.
- Implement project/user preferred destinations and document alternative discovery paths separately.
- Verify reserved names, environment overrides, duplicate-skill behavior, symlink discovery, and version restrictions relevant to copying.
- Use one adapter record per materially different product/runtime variant.
- Document that selecting a host chooses a write destination, not exclusive visibility to that host.

## Acceptance criteria

- [ ] Every shipped path/scope/platform rule has a current primary source and resolver test.
- [ ] The preferred project destinations are verified against official docs, not copied from third-party registries.
- [ ] Known shared-reader effects are surfaced; selecting Codex does not promise that OpenCode cannot see the skill.
- [ ] Unsupported or undocumented OS details are flagged rather than inferred.
- [ ] No writes target managed, bundled, or cloud-only stores.

## Verification

- Test core-target resolution for each documented scope.
- Test duplicate requested targets and compatibility-path overlap.
- Test reserved names and unsupported variants where documentation requires them.
