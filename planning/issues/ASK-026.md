# ASK-026: Complete the OSS visibility and first-release approval gate

## Goal

Prepare a maintainer decision on making the repository public and shipping v0.1.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This repository is private during development and is intended for a future English-language OSS release.

## Scope

- Audit tracked files, full Git history, issues, PRs, project descriptions, CI logs, artifacts, and links for private data or credentials.
- Confirm naming, licensing, contributor attribution, security reporting, and documentation completeness.
- Review evidence for every shipped adapter; deferred catalog candidates need not block v0.1 but must not be advertised as supported.
- Review repository and Project visibility separately; do not assume one changes the other.
- Record distinct human approvals for repository publication, optional Project publication, crates.io publishing, and GitHub binary releases.

## Acceptance criteria

- [ ] A completed release checklist cites the candidate commit and CI results.
- [ ] All advertised targets have current evidence and the promised test coverage.
- [ ] Unresolved critical safety issues block publication.
- [ ] No private conversation content or guessed contact information remains.
- [ ] Visibility and actual publication stay unchanged until the maintainer explicitly approves each action.

## Verification

- Perform an independent review of the history and public-facing material.
- Verify reporting routes and package contents.
- Record approval or specific remaining blockers in the issue.

## Non-goals

This planning issue is not standing authorization to make anything public. Do not flip repository/Project visibility or run publishing commands automatically.

## Primary references

- https://doc.rust-lang.org/cargo/reference/publishing.html
- https://docs.github.com/en/issues/planning-and-tracking-with-projects/automating-your-project/using-the-api-to-manage-projects

## Handoff

Open a focused PR with `Closes #<actual-issue-number>`. Report commands actually run, results, untested platforms, and any remaining risks. Do not merge or publish without maintainer approval.
