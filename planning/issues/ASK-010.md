# ASK-010: Implement staged copy execution with no-clobber defaults

## Goal

Apply an approved plan without silently overwriting existing skills.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This is a WIP, not-ready-for-use English-language OSS source preview, not a supported or published library/CLI. Source visibility is separate from crate and binary publication; see `docs/public-readiness.md` and `docs/release.md`.

## Scope

- Stage on the destination filesystem, copy validated regular files, validate staged output, and commit using the reviewed platform strategy.
- Revalidate plan preconditions and source identity/content; handle mutation between inventory and copy.
- Do not follow destination descendant symlinks or Windows reparse points. Reject unsafe parent changes.
- Return per-destination outcomes and an actionable partial-failure report.
- Limit cleanup to paths created and still owned by this operation.

## Acceptance criteria

- [ ] New installations include SKILL.md and all allowed supporting files.
- [ ] Existing different content is never overwritten by default or by --yes.
- [ ] Failed staging leaves preexisting content untouched; cleanup never removes unrelated data.
- [ ] A stale plan is rejected or explicitly replanned, not applied blindly.
- [ ] No skill code or external package-manager command is executed.
- [ ] Documented guarantees match the tested OS implementations, including no-replace and race limitations.

## Verification

- Inject copy, permission, rename, and interrupted-operation failures.
- Test source changes and destination races with deterministic synchronization.
- Run native Linux/macOS/Windows tests and verify returned reports.

## Non-goals

Do not implement destructive replace, uninstall, downloads, or symbolic-link installation. Split backend-specific work into sub-issues if the safety strategy is too large for one review.

## Handoff

Open a focused PR with `Closes #<actual-issue-number>`. Report commands actually run, results, untested platforms, and any remaining risks. Do not merge or publish without maintainer approval.
