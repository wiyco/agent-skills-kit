# ASK-029: Design managed upgrades and safe uninstall

## Goal

Add lifecycle management without deleting or overwriting unmanaged user content.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This is a WIP, not-ready-for-use English-language OSS source preview, not a supported or published library/CLI. Source visibility is separate from crate and binary publication; see `docs/public-readiness.md` and `docs/release.md`.

## Scope

- Use explicit receipts and digests to identify files owned by an installation.
- Define modified-file conflicts, backups, recovery, and preview semantics.
- Require an explicit separate operation for replace/update/uninstall; --yes never becomes force.
- Do not claim a transaction across multiple filesystem roots.

## Acceptance criteria

- [ ] Unmanaged and locally modified content is preserved by default.
- [ ] Every destructive action has a read-only preview and explicit authorization.
- [ ] Concurrent changes are detected.
- [ ] Recovery behavior is documented and tested per supported OS.

## Verification

- Test changed, missing, moved, and corrupt receipt scenarios.
- Inject failures during backup/replace/remove operations.
- Review symlink and reparse-point escapes.

## Non-goals

Do not expand this issue into unrelated roadmap work.

## Handoff

Open a focused PR with `Closes #<actual-issue-number>`. Report commands actually run, results, untested platforms, and any remaining risks. Do not merge or publish without maintainer approval.
