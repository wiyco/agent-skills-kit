# ASK-027: Design opt-in symbolic-link installation

## Goal

Evaluate link-based installation after safe copying is released.

## Context

Read `AGENTS.md`, `docs/architecture.md`, and `docs/testing.md` before implementation. This repository is private during development and is intended for a future English-language OSS release.

## Scope

- Verify host support and native OS behavior for links/junctions with current evidence.
- Define link ownership, dangling-link behavior, cleanup, and explicit fallback policy.
- Keep copy as the default and link mode opt-in.
- Test Windows privilege limitations without silently falling back.

## Acceptance criteria

- [ ] A reviewed ADR defines guarantees and unsupported cases.
- [ ] No existing destination is replaced by a link without separate consent.
- [ ] Supported hosts have documented discovery evidence.
- [ ] Link-specific tests are isolated from source-symlink policy tests.

## Verification

- Run native link/reparse-point tests.
- Test dangling targets and moved sources.
- Verify declared host behavior.

Do not expand this issue into unrelated roadmap work.
